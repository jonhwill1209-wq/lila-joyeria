# Product Backlog — API REST

Este backlog cubre el incremento REST integrado con la aplicación existente.
Prioridad: P1 es necesaria para el alcance solicitado; P2 es mejora posterior.

| ID | Prioridad | Historia / criterio de aceptación | Estado |
|---|---|---|---|
| API-01 | P1 | Como consumidor, consultar el catálogo y una joya por ID en JSON. | Hecho |
| API-02 | P1 | Como administrador, crear, actualizar y eliminar joyas con validación y persistencia. | Hecho |
| API-03 | P1 | Restringir mutaciones a ADMIN y proteger datos de sesión/credenciales. | Hecho |
| API-04 | P1 | Consumir la API desde el cliente web con estados de carga y error. | Hecho |
| API-05 | P1 | Ejecutar casos positivos, negativos y de límites en Postman. | Preparado; ejecutar y adjuntar resultado del Runner |
| API-06 | P1 | Publicar contrato, restricciones, respuestas, seguridad y guía de consumo. | Hecho |
| API-07 | P1 | Centralizar la salida JSON de errores y registrar errores/operaciones relevantes. | Hecho |
| API-08 | P2 | Publicar OpenAPI/Swagger si el curso o el despliegue lo requiere. | Pendiente |
| API-09 | P2 | Desplegar el cliente en un origen/proceso independiente de Tomcat. | Cliente configurable para despliegue separado; el despliegue público aún no se ha realizado |
| API-10 | P2 | Automatizar pruebas HTTP de integración con una base aislada para CI. | Pendiente |
